# Project Memory

_Notes for Claude (and future contributors) on this project. Durable facts only — see PROJECT_MEMORY skill for what belongs here._

## Overview
Fridgo ist eine Flutter-App für Android und iOS, die den Lebensmittelbestand über mehrere Wohnungen zeigt, lokal und offline. Ziel, Umfang, Architektur und Regeln stehen in `CLAUDE.md`; hier steht nur, was dort und im Code nicht steht.

## Bugs Fixed & Gotchas
- `make build-ios` bricht mit „Application not configured for iOS" ab, wenn `xcode-select -p` auf die CommandLineTools statt auf `/Applications/Xcode.app` zeigt. Die Meldung hat nichts mit dem Projekt zu tun. Seit 2026-10-13 ist Xcode installiert und aktiv; `make build-ios` läuft lokal durch.

- Noto Emoji: Die README nennt Apache 2.0 für Bilder, die `LICENSE` im Repo-Root ist aber inzwischen OFL 1.1 — die LICENSE gilt. Einzelne SVGs (z. B. `emoji_u1f37d.svg`, Teller) sind Illustrator-Exporte mit DOCTYPE-Entities und eingebettetem Binärblock; vor der Übernahme mit `grep DOCTYPE` prüfen.
- Ein Emulator, der in einem Bash-Aufruf mit `&` gestartet wird, stirbt mit dem Ende des Aufrufs. Als eigenen Hintergrundprozess starten (`~/Library/Android/sdk/emulator/emulator -avd Pixel_8`; seit 2026-10-15 heißt die AVD so, `-list-avds` prüfen). Läuft schon einer (ohne Fenster), `adb devices` nutzen statt einen zweiten zu starten. Für UI-Abläufe ohne Fenster: `adb shell input tap/text/keyevent` und `adb exec-out screencap -p`; der iOS-Simulator hat hier kein Eingabewerkzeug. `make run` meldet beim Installieren `INSTALL_FAILED_INSUFFICIENT_STORAGE`, deinstalliert dann die alte Version und kommt im zweiten Anlauf durch.

- iOS-Simulator (seit 2026-10-15 Runtime iOS 27.0): `Simulator.app` fehlt in dieser Xcode-Installation, der Simulator läuft ohne Fenster. Start mit `xcrun simctl boot <UDID>`, App mit `make run FLUTTER="fvm flutter -d <UDID>"` (ohne `-d` fragt `flutter run` interaktiv nach dem Gerät), Screenshots mit `xcrun simctl io <UDID> screenshot`, Hell/Dunkel mit `xcrun simctl ui <UDID> appearance dark`.
- drift-Migrationstest: `verifier.startAt(n)` + `migrateAndValidate(db, n)` vergleicht den abgelegten Stand mit sich selbst und schlägt nie fehl. Um zu prüfen, ob der Code zum abgelegten Stand passt, eine frische `AppDatabase(NativeDatabase.memory())` an `migrateAndValidate` geben. Für echte Upgrades gilt `startAt(alt)` → `migrateAndValidate(db, neu)`.
- build_runner 2.17.1 (erschienen 2026-10-14) verlangt `build` 5, drift_dev 2.35.1 und freezed 4.0.2 nur `build` <5, 2.17.0 ist nicht auflösbar. Deshalb `build_runner: ^2.16.2`. Hochziehen, sobald drift_dev und freezed `build` 5 unterstützen.
- `watch().first` eines drift-Streams wird in der FakeAsync-Zone von `testWidgets` nie fertig, `get()` schon. Code, der beim App-Start einmal liest (Start-Redirect), nutzt deshalb `get()` (`HomeRepository.getHomes`). Symptom: Start-Screen fehlt, danach hängt `flutter test` ohne Abschlussmeldung.
- Ein drift-Stream liefert seine erste Abfrage asynchron; ein sofort danach eingefügter Datensatz kann schon in der ersten Ausgabe stecken. Im Test erst `listen` + `pumpEventQueue()`, dann einfügen.
- drift in `testWidgets`: Datenbank über `createWidgetTestDatabase()` (`test/data/database/test_database.dart`, `closeStreamsSynchronously: true`), sonst bleibt ein Timer offen. Direkte Repository-Schreibzugriffe im Widget-Test (auch in `tester.runAsync`) hängen gegen die FakeAsync-Zone; Daten über die Oberfläche anlegen, Lesen in `runAsync` geht.
- Riverpod 3 pausiert Provider ohne Zuhörer: `container.read(provider.future)` auf einen Stream-Provider hängt, solange kein `container.listen` besteht. Im Teardown erst `container.dispose()`, dann die Datenbank schließen.
- SQLite prüft Fremdschlüssel nur mit `PRAGMA foreign_keys = ON` pro Verbindung; das steht seit T006 in `beforeOpen` von `AppDatabase`. Ohne die Zeile laufen Inserts mit unbekannter `homeId` still durch.
- Android-Emulator: `adb` liegt unter `~/Library/Android/sdk/platform-tools/adb` und ist nicht im `PATH`. Ein schwarzer Screenshot heißt meist, dass das Display schläft: `input keyevent KEYCODE_WAKEUP` und `wm dismiss-keyguard`. `adb install -r build/app/outputs/flutter-apk/app-debug.apk` aktualisiert und behält die Daten, gut zum Prüfen von Migrationen am Gerät.
- `make run` im Hintergrund: Die Ausgabe von `flutter run` bleibt bei „Running build hooks…“ stehen, obwohl die App längst läuft. Mit einem Screenshot prüfen statt auf die Ausgabe zu warten.
- `--delete-conflicting-outputs` ist in build_runner 2.16 entfernt und wird nur mit Warnung ignoriert.
- `make test TESTS=<Datei oder Ordner>` führt nur einen Teil der Tests aus. Kompiliert eine Testdatei nicht oder schlägt ein Widget-Test fehl, kann `flutter test` ohne Abschlussmeldung hängen bleiben (T010: ein fehlgeschlagener Test im Formular-Test). Dann Ordner einzeln mit Ausgabe in eine Datei laufen lassen und die Datei lesen; `timeout` gibt es auf macOS nicht, und hinter `| tail` sieht man bis zum Ende nichts.
- drift `TypedResult.read(expr)` als Rückgabe einer `async`-Funktion: Dart leitet den Typparameter aus dem Rückgabekontext als `FutureOr<int>` ab, der Lint `async_return_with_no_await` schlägt an. `read<int>(count)` schreiben.
- Ein `make run`, das noch läuft (auch aus Android Studio oder einer anderen Session), hält die Flutter-Startsperre; `make test` hängt dann bei „Waiting for another flutter command to release the startup lock“. Mit `ps` prüfen und den Nutzer fragen, statt zu killen.
- `DateTime` hat keinen `const`-Konstruktor: Data-Provider-Maps mit `DateTime` sind `final`, nicht `const`.
- Gelesenes „heute“ veraltet leicht: Die Übersicht bleibt unter dem Hinzufügen-Screen und im Hintergrund über Nacht erhalten. Ein Provider, der die Uhr nur einmal liest, zeigt morgens den Stand von gestern (T009, am Gerät aufgefallen). Wer künftig die Uhr in der UI liest (Erinnerungen, T024), braucht dieselbe Auffrischung.
- `ThemeData.textTheme` hat beim Bauen des Themes noch keine Schriftgrößen (die kommen erst über `Theme.of` dazu). Ein Stil aus `base.textTheme` in einem Komponenten-Theme (z. B. `DialogThemeData.titleTextStyle`) fällt auf 14 px zurück; stattdessen den Stil im `textTheme` selbst ändern (T018: `headlineSmall` fett für den Dialogtitel).
- Die Emulator-Systemzeit lässt sich nicht per `adb shell date` setzen (kein Root im Produktions-Image); Datumswechsel deshalb per Widget-Test mit veränderlicher Uhr und `handleAppLifecycleStateChanged` prüfen.
- Formulare nicht in einem `ListView` bauen: Felder außerhalb des sichtbaren Bereichs werden nicht gebaut, und `Form.validate()` prüft sie nicht. Das Hinzufügen-Formular ist seit T010 `SingleChildScrollView` + `Column`. Eine Snackbar über dem Speichern-Knopf lässt `tester.tap` im Widget-Test danebengehen; vorher `pump(5 s)`.
- Android-Emulator: Die Kamera liefert eine virtuelle Szene, der Photo Picker ist leer, bis man ein Bild nach `/sdcard/Pictures` pusht und `content call --method scan_volume --uri content://media --arg external_primary` ausführt. App-Dateien prüfen mit `adb shell run-as io.worlddomination.fridgo ls app_flutter cache`, die Datenbank per `adb exec-out run-as … cat app_flutter/fridgo.sqlite > x.sqlite` und Host-`sqlite3` (auf dem Gerät fehlt es).
- Der iOS-Simulator ohne Eingabewerkzeug zeigt nur den Startscreen; Abläufe (Anlegen, Speichern, Neustart) werden am Android-Emulator geprüft, iOS nur per Build und Screenshot.
- Bilder aus Dateien im Widget-Test: Das Laden hängt, wenn `FileImage` in der FakeAsync-Zone startet. `pumpWidget`, `pump` und `precacheImage(..., onError: ...)` gemeinsam in `tester.runAsync`, danach `pumpAndSettle` (siehe `product_thumbnail_test.dart`).
- Lasttest am Gerät ohne Seed-Code in der App: App mit `am force-stop` beenden, Datenbank und `product_images/` per `exec-out run-as … cat` sichern, Kopie mit Python/`sqlite3` befüllen, nach `/data/local/tmp` pushen und per `run-as … cp` zurückkopieren; danach nicht blind die Sicherung zurückspielen: Der Nutzer legt zwischendurch echte Daten an (T011: eine Wohnung, fünf Bestände). Stattdessen nur die Testwohnung samt Produkten und Bildern löschen und außerhalb davon per `EXCEPT` gegen den aktuellen Stand vergleichen. Ein Profil-Build (`make run-profile`) installiert über den Debug-Build und behält die Daten. Die Shell hier ist zsh: Arrays beginnen bei 1, für Skripte Python nehmen.
- Das eigene Gerät des Nutzers (Android 12) hängt per WLAN-Debugging an `adb` und trägt echte Daten; vor Eingriffen sichern.
- Integrationstest: `pumpAndSettle` wartet nicht auf Antworten aus einem anderen Isolate. Mit `NativeDatabase.createInBackground` (wie `driftDatabase` in der App) war der Startbildschirm beim Kaltstart manchmal noch nicht gebaut („Wohnung anlegen“ nicht gefunden). Der Test öffnet die Datei deshalb mit `NativeDatabase(file)` im selben Isolate.
- `flutter test integration_test` deinstalliert die App nach dem Lauf (`--uninstall` ist Standard) und löscht damit alle App-Daten; `make integration-test` setzt deshalb `--no-uninstall`. Danach ist die Test-App installiert; `make build-android` + `adb install -r build/app/outputs/flutter-apk/app-debug.apk` stellt die echte App am Emulator wieder her, die Daten bleiben. Globales `-d` (`FLUTTER="fvm flutter -d <id>"`) wirkt auch für `flutter test`; auf dem Headless-iOS-Simulator läuft der Test ohne Weiteres.
- Golden-Tests: `flutter_test` zeichnet Schatten als schwarze Kontur (`debugDisableShadows`), Text mit Kästchenschrift und lädt Fotos/SVGs in der FakeAsync-Zone nie. `test/ui/golden.dart` löst alles drei (`testGolden`, `loadAppFonts`, `pumpAndLoadImages`). `debugDisableShadows` muss noch im Testkörper zurückgesetzt werden, `addTearDown` ist zu spät. Daten aus Stream-Overrides und der Dateipfad aus `productImageFileProvider` kommen erst über mehrere Frames, vorher gibt es kein `Image` zum Vorladen.
- Widget-Tests mit großem Foto oben: Die Standard-Testfläche (800 × 600) füllt das 4:3-Foto fast ganz, der `ListView` baut die Zeilen darunter nicht. Testfläche auf Handygröße setzen (`tester.view.physicalSize = Size(1080, 2340)`, `devicePixelRatio = 3`).
- Übergänge am Emulator prüfen: `adb shell screenrecord --time-limit 4 /sdcard/x.mp4` im Hintergrund, dann tippen; ffmpeg und PIL fehlen auf dem Mac, Einzelbilder per Swift-Skript mit `AVAssetImageGenerator`. Im Debug-Build fehlen die Bilder des ersten Übergangs oft ganz; die Flüssigkeit nur im Profil-Build oder am Gerät beurteilen.
- Widget-Test-Helfer, die nach `enterText` per `ensureVisible` zu einem Knopf scrollen: Das fokussierte Feld scrollt im nächsten Frame zum Cursor zurück und schiebt den Knopf wieder aus der Testfläche (T019, „tap … would not hit test“). Vor `ensureVisible` erst `pumpAndSettle`.
- Der Dart-MCP-Server (`fvm dart mcp-server`) ist seit 2026-10-15 lokal für dieses Projekt eingetragen (`claude mcp add dart`, Scope local, nicht im Repo). Maßgeblich für „fertig“ bleibt `make check`.
- SQLite kann per `ALTER TABLE ADD COLUMN` keine UNIQUE-Spalte anlegen. Eindeutigkeit für eine neue Spalte als eigener Index: `@TableIndex(..., unique: true)` an der Tabelle und `m.createIndex(schema.<index>)` im Migrationsschritt (T029).
- mobile_scanner 7: `controller.start()` wirft bei Plattformfehlern (Berechtigung verweigert, keine Kamera) nicht, sondern setzt `controller.value.error`; danach prüfen. Mit eigenem Controller pausiert das `MobileScanner`-Widget bei App-Wechsel nicht selbst. `start()` wartet bis 500 ms darauf, dass das Widget im Baum hängt, die Vorschau muss also im selben Frame gebaut werden.
- Seit `mobile_scanner` steht `CAMERA` im zusammengeführten Android-Manifest; „Foto aufnehmen“ (`image_picker`) fragt deshalb ohne erteilte Berechtigung einmal nach der Kamera (am Emulator geprüft, funktioniert).
- Eine Snackbar der vorigen Seite liegt im `body` über Knöpfen am unteren Rand (Scanner: „Ohne Barcode“). Knöpfe dort in `bottomNavigationBar` legen, dann erscheint die Snackbar darüber.
- Berechtigungsdialog am Emulator erneut auslösen: `pm revoke <app> android.permission.CAMERA` und `pm clear-permission-flags <app> android.permission.CAMERA user-set user-fixed` (beendet die App), dann neu starten. Der Headless-Emulator verliert beim Öffnen der Kamera gelegentlich die Verbindung („bad color buffer handle“, „device offline“) und startet neu; dann den Ablauf wiederholen, bevor man einen App-Fehler annimmt.
- Integrationstest auf dem Emulator: `addStockItem` (`test/ui/app_flows.dart`) wartet vor Tipps mit `pumpAndSettle` + `ensureVisible`, sonst geht „Hinzufügen“ am Gerät daneben und nichts wird gespeichert (der Fehler zeigt sich erst beim nächsten `expect`).
- Release-Build blieb schwarz (T038): `shared_preferences_android` 2.5.0 hatte keine R8-Regeln für seine JNI-Klassen → `NoSuchMethodError` im Start-Redirect; erst `logcat | grep "E flutter"` zeigt es. Behoben mit 2.5.3 (`make upgrade PACKAGES=…`). Danach scheiterte der Build an alten Plugin-Resten (`Symbol nicht gefunden: SharedPreferencesPlugin`); `build/<plugin>` löschen hilft. Debug/Profil zeigen solche Fehler nicht, deshalb Netz- und Plattformänderungen mit `make run-release` prüfen.
- Abläufe am Emulator ohne Koordinaten raten: `adb exec-out uiautomator dump /dev/tty` liefert Knoten mit `text`/`content-desc` und `bounds`; Textfelder tragen ihr Label nur im Attribut `hint`. Die Vorschlagsliste des Namensfelds liegt über den Lagerort-Chips, ein Tipp dorthin wählt einen Vorschlag; vorher Tastatur und Liste schließen. Die gedebuggte Debug-APK startet per `monkey` auch ohne `flutter run`, braucht aber ~10 s.
- Android-Emulator, virtuelle Kamera: `adb emu virtualscene-image wall|table <png>` setzt ein Poster, aber Headless lässt sich die Szene nicht drehen (`sensor set acceleration` wirkt nicht); Barcodes daher nicht am Emulator scannbar, nur am Gerät.
